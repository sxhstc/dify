# OneSpec Implement Change

此命令用于执行具体的开发任务。它会读取设计文档和任务列表，指导代码变更的实施。

<background_information>
- **任务**: 基于已批准的规范，根据详细设计执行实现任务
- **成功标准**:
  - 任务在 tasks.md 中标记为已完成
  - 实现与设计和需求保持一致
</background_information>

<instructions>
<!-- START -->
## 参数
- `id`: (可选) 需求/变更ID。如果上下文中能明确推断出唯一ID，可省略。
- `name`: (可选) 变更名称。如果上下文中能明确推断出唯一名称（例如当前已在变更目录下），可省略。
- `task_id`: (可选) 指定执行的任务：`禅道任务ID`（tasks.md 中）或 tasks.md 中的序号。不指定则列出待处理任务。

## 执行步骤

### 1. 准备工作与校验
1.  **上下文识别与参数补全**:
    - **自动推断**:
        - 检查当前活跃的编辑器文件路径，是否包含 `onespec/changes/<id>-<name>/` 模式。
        - 检查最近的对话历史或工具调用，是否刚执行过 `onespec-change` 或 `onespec-design`。
    - **参数确认**:
        - 如果用户提供了 `id` 和 `name`，直接使用。
        - 如果用户仅提供了 `id`，尝试在 `onespec/changes/` 目录下查找匹配该 ID 的目录，自动补全 `name`。
        - 如果用户未提供参数，且通过上下文推断出唯一的 `<id>-<name>`，则自动使用。
        - 如果推断出多个可能性，列出选项请用户确认。
        - 如果无法推断，提示用户输入必需参数。
2.  **检查 Proposal**:
    - 验证 `onespec/changes/<id>-<name>/proposal.md` 是否存在。
    - 若不存在，终止并提示: "请先执行 `onespec-change` 创建变更提案。"
3.  **检查 Design**:
    - 验证 `onespec/changes/<id>-<name>/design.md` 是否存在。
    - 若不存在，终止并提示: "请先执行 `onespec-design` 完成详细设计。"
4.  **检查 Tasks**:
    - 验证 `onespec/changes/<id>-<name>/tasks.md` 是否存在。
    - 若不存在，终止并提示: "未找到任务列表，请重新运行 `onespec-design`。"

### 2. 任务选择与上下文加载
1.  **读取任务列表**:
    - 解析 `onespec/changes/<id>-<name>/tasks.md`。
    - 筛选出状态为 "未处理" 或 "进行中" 的任务。
2.  **确定目标任务**:
    - 如果提供了 `task_id`，定位对应任务。
    - 如果未提供，展示待处理任务列表，提示用户选择 (或按顺序执行第一个)。
3.  **加载上下文**:
    - 读取 `design.md` 中与该任务相关的章节。
    - 读取 `specs/` 下相关的 Delta Spec。
    - 读取 `proposal.md` 中的背景信息。
    - **更新 Proposal 状态**:
        - 读取 `onespec/changes/<id>-<name>/proposal.md`。
        - 检查 `status` 字段。
        - 如果当前状态不是 `implementing`，将其更新为 `implementing`。

### 3. 代码生成与变更 (Coding)
1.  **分析现有代码**:
    - 根据设计文档中提到的文件和模块，搜索代码库中的相关位置。
2.  **生成代码变更**:
    - 依据任务描述和设计规范，生成代码变更。
    - **遵循原则**:
        - 保持代码风格一致。
        - 遵守项目规范 (相关 `.mdc` 规则)。
        - 优先实现核心逻辑，随后处理边缘情况。
3.  **应用变更**:
    - 使用编辑工具修改源代码。

### 4. 任务状态更新
1.  **更新本地状态**:
    - 修改 `tasks.md` 中对应任务的状态为 "已完成" (Completed) 或 "进行中" (In Progress)。
2.  **同步禅道 (可选/建议)**:
    - 通过 **禅道 MCP**（`user-zentao`）调用 **`put_tasks_taskID_finish`** 完成任务：`taskID` = 该任务的 `禅道任务ID`，`payload` 中填写 `currentConsumed`（实际工时）等字段。
    - 若任务无禅道任务 ID 则跳过同步。

### 5. 结果反馈
- 输出: "任务 [ID] - [标题] 执行完毕。"
- 提示: "请运行单元测试或手动验证变更。完成后可选择下一个任务。"

## 关键约束
- **任务范围**: 仅实现特定任务要求的
- **设计对齐**: 实现必须遵循 design.md 规范
- **设计反馈**: 若在实现过程中发现设计有误或不可行，**必须暂停任务**并提示用户更新设计文档，严禁擅自偏离设计。
- **路径基准**: 命令中的文件读写路径以本命令文件所在仓库的根目录为基准，不限制跨工作区的上下文收集。
</instructions>
