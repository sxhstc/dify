# OneSpec 提测清单 (Checklist)

根据 **禅道执行（Execution）ID** 拉取该执行下**全部工作项**，汇总后生成与测试中心结构一致的 `checklist.md`。

**禅道 MCP**：服务器名为 **`user-zentao`**（以 Settings → MCP 为准）。执行与工作项使用 **`get_executions_executionID`**（执行详情）、**`get_executions_executionID_stories`**（需求）、**`get_executions_executionID_tasks`**（任务）、**`get_executions_executionID_bugs`**（Bug）。

<background_information>
- **任务**: 产出可提交测试中心（或复制粘贴）的提测材料；**执行信息、工作项列表须来自禅道 MCP 返回**，不得凭空编造。
- **输入**:
  - `executionID`（必填）— **禅道执行 ID**（Execution ID，与禅道执行详情 URL/接口中的执行标识一致）。
  - `projectID`（选填）— 禅道**项目** ID。未提供时可从 `get_executions_executionID` 返回的 `project` 字段获取。
  - `镜像id` / `imageId`（选填）— **容器镜像 ID，可多个**（多服务/多制品时用空格或逗号分隔多个 id，或提测前在第二节表格逐行手写）；规则见「镜像 id 确认」。
- **输出**: `onespec/checklist/<执行目录名>/checklist.md`。其中 **`<执行目录名>` 不使用执行 ID**，而是 **`get_executions_executionID` 返回的执行 `name` 经文件名安全化后的 slug**（见步骤 8）；执行 ID 仅写在 `checklist.md` Frontmatter 的 `zentao-execution-id` 中。
- **成功标准**:
  - 已**至少一次成功**调用禅道 MCP 取得该执行下工作项列表（可为空列表，但须为真实 API 结果）。
  - 清单中含 **执行内工作项清单**（表或结构化列表）及一至八节；**第三节「涉及的接口」** 以 **「接口列表」** 表格为主，子表按需；**第四节**为**文本**；第四节无 SQL 时可留空。
</background_information>

## 参数

- `executionID`: (必填) **禅道执行 ID**（Execution ID）。
- `projectID`: (选填) 禅道 **项目 ID**。未提供时从执行详情的 `project` 字段获取。
- `镜像id` / `imageId`: (选填) **容器镜像 ID，可传多个**（分隔符：逗号、分号或空格）；与第二节表格多行一一对应；未提供时不得编造，须执行「镜像 id 确认」后再写入。

## 执行步骤

### 1. 禅道：执行与工作项列表

1. **获取执行详情**：调用 **`get_executions_executionID`**（`executionID`），记录执行名称（`name`）、起止时间、所属项目（`project` 字段）等元数据。若返回 404，提示用户核对执行 ID，终止。

2. **解析 `projectID`**（若用户未提供）：从执行详情返回中取 `project` 字段即为 `projectID`。

3. **枚举执行内全部工作项**（分三类 API 调用后合并）：
   - 调用 **`get_executions_executionID_stories`**（`executionID`）→ 获取需求列表，每条标记类型为 **Story**。
   - 调用 **`get_executions_executionID_tasks`**（`executionID`）→ 获取任务列表，每条标记类型为 **Task**。
   - 调用 **`get_executions_executionID_bugs`**（`executionID`）→ 获取 Bug 列表，每条标记类型为 **Bug**。
   - 汇总每条并填入「执行内工作项」表：**ID**（`id`）、**禅道编号**（按来源格式化为 `Story-<id>` / `Task-<id>` / `Bug-<id>`）、**标题**（`title`）、**需求等级**（优先从工作项描述或自定义字段解析，如「B 级」；无则查本地 `onespec/prd/**/prd.md` 或标 **TBD**）、**优先级**（`pri` 字段；无则 **TBD**）、**类型**（Story/Task/Bug）、**状态**（`status`）。
   - **失败**：提示检查 `executionID`、MCP 与网络，终止。
   - **列表为空**：在清单中如实写「本执行下未检索到工作项」，仍生成清单骨架；第一节业务逻辑可写「无关联工作项描述，请从禅道核对筛选条件」。

4. **解析「提测版本」**（写入 Frontmatter / 第一节）：
   - 优先：**执行名称 + 起止日期**（来自 `get_executions_executionID`）。
   - 辅以：各工作项自定义字段、标签中的版本/分支信息。
   - 仍无明确版本号：填 **`TBD`** 并说明原因。

5. **镜像 id**：**不由 MCP 自动作为最终值写入**；禅道返回中若有镜像相关字段仅作**提示**；落盘以用户提供的 **一个或多个** id 为准，或经用户同意后对**缺失行**使用「待填写」。**多个镜像**时第二节表格**多行**；**「应用名」列填本仓库 Git 仓库名**（如 **`bfs-bemp`**），与 **镜像 id** 成对；**不填** Maven 子模块名作为应用名。

### 2. 关联 OneSpec 目录（按执行内工作项逐项）

对 **执行内每个工作项 ID**，按**先后顺序**查找本地文档（命中即用，勿重复读取）：

1. **`onespec/changes/<workItemId>-<name>/`**：目录名以工作项 ID 为前缀。
2. 若 **changes 下不存在**：**可能已执行 `onespec-complete` 归档**（原 `changes/` 目录已迁移删除）。此时在 **`onespec/archive/`** 下检索：归档路径形如 **`onespec/archive/<yyyyMMdd>-<workItemId>-<name>/`**（见 `onespec-complete`），可用 `Glob` 匹配 `onespec/archive/*-<workItemId>-*/` 或等价方式定位目录。
3. 在**上述任一命中目录**中读取存在的 `proposal.md`、`design.md`、`tasks.md`，**合并**到后续章节（多份设计取并集去重说明，冲突处标 TBD 并列出工作项 ID）。

若 **changes 与 archive 均未找到**该工作项对应目录：在清单第七节「相关文档」或内部备注中引导检索 `changes` / `archive`；**禁止**在第一节「详细说明」中堆砌 OneSpec 路径与归档过程说明（第一节仅业务语义）。**禁止**将「未找到」简单写成「从未创建」而忽略已归档情形。

### 2.1 第一节「涉及改动的业务逻辑描述」（单需求 / 多需求）

- **呈现形式**：**「改动摘要」「详细说明」均使用表格**；**详细说明**只写业务语义，不写技术实现、不写工作项长 ID、不写文档路径。
- **可省略行**：**改动摘要**中「交付形态」「数据与范围」无特别说明时不列；**详细说明**中「使用场景」「角色与权限」「鉴权失败」等无特别说明或与业务目标重复时不列。
- **单需求**：**改动摘要**用 **「维度 | 内容」**（至少「需求」「业务目标」）；**详细说明**用 **「说明项 | 内容」**（与当前 `spec-templates/checklist.md` 示例一致）。
- **多需求**：
  - **改动摘要**：可选一句执行级总述后，用 **「禅道编号 | 标题 | 业务改动摘要」**，**一行一条需求**；摘要为业务一句话（原状 → 新能力/规则），不写接口路径与类名。
  - **详细说明**：**方式 A** — **「禅道编号 | 说明项 | 内容」** 三列表，同一需求行连续排列；**方式 B** — 每个需求 `#### <禅道编号> <标题>` 下接 **「说明项 | 内容」** 表。多份 `proposal`/`design` 冲突时在表中或表下用 **TBD** 标禅道编号。
- **第三～八节**：接口 / SQL / 配置 / 测试关注点等仍**合并**全部工作项内容（去重）；第一节是按**需求维度**让读者先看业务，避免多需求时揉成一段。

### 3. 代码与仓库检索（填充二～五节）

1. **应用（二）**：**应用名 | 镜像 id** 两列表格；**「应用名」= 仓库名**（如 **`bfs-bemp`**）；**支持多行**（多镜像时同仓库名可重复多行）；若用户传入多个 `镜像id`，按顺序与各行镜像 id 对应；**不填** bemp-server 等子模块作为应用名。
2. **接口（三）**：合并所有关联 `design.md` 与代码检索结果，**使用表格描述**；**至少**「接口列表」一行一条；**路径参数 / 成功响应 / 异常与鉴权等子表**仅在有**特别说明**（与惯例或 PRD 不一致、非标约定等）时追加，无则省略。
3. **SQL（四）**：合并所有变更相关 SQL 说明；**文本**；无则整节留空。
4. **配置（五）**：合并配置项；**不脱敏**。

### 4. 测试关注点（六）

- 综合所有关联 `proposal.md` / `design.md` 与执行内工作项描述的验收点。

### 5. 相关文档（七）

- 列出本仓库内关联路径：**`onespec/changes/<id>-<name>/`**（若仍存在）与/或 **`onespec/archive/<yyyyMMdd>-<id>-<name>/`**（若已从 `onespec-complete` 归档）、`onespec/prd/**` 及本 `checklist.md` 路径。

### 6. 自测结果（八）

- 保留表头；不编造测试结果。

### 7. 镜像 id 确认（写入前必须满足）

1. 若参数或对话中已给出 **一个或多个** 镜像 id → 按顺序填入第二节表格多行，并在 Frontmatter「镜像id」中写摘要或并列列出。
2. 若**部分**镜像缺失：**暂停生成文件**，询问用户补全剩余 id，或是否同意对**未提供的行**使用 **「待填写」**。
3. 若**完全未提供**镜像 id：**暂停生成文件**，询问用户提供（可多个），或是否同意**全部行**暂用「待填写」；**收到明确回复后**再执行步骤 8。
4. **禁止**：未完成确认前写入**虚假**镜像 id（「待填写」视为占位，非伪造）。

### 8. 生成文件

1. **清单正文排版（须遵守）**：
   - Frontmatter 增加 **`zentao-project-name`**：禅道**项目中文名**（来自 `get_executions_executionID` 返回的项目信息，或通过 `projectID` 获取）。
   - 标题 **`# 提测清单 — …`** 之后、**仅**保留模板中的 **执行/禅道项目** 三列表格（中文名称 + ID），**禁止**写入「本文档对齐测试中心提测单结构」「范围为本禅道执行内全部纳入检索的工作项（见下表）」等套话或引导语。
   - **「## 执行内工作项」** 下**仅**工作项表格；**禁止**在正文出现「以下自禅道 MCP…」等 MCP/检索过程说明（该类说明只存在于本命令，不进入清单）。
   - **「## 一、涉及改动的业务逻辑描述」**：**改动摘要**、**详细说明**须用**表格**（见 **§2.1** 单需求 / 多需求）；无特别说明时不列「交付形态」「数据与范围」「使用场景」「角色与权限」「鉴权失败」等常规套话行；**禁止**在「详细说明」中写入 OneSpec 路径、`archive`、工作项长 ID、技术实现类名；多需求时「改动摘要」用「禅道编号 | 标题 | 业务改动摘要」逐行区分。
   - **「## 二、涉及改动的应用」** 下**禁止**输出「**本仓库定位**…」「**镜像可能有多个**…」等说明段；**禁止**把模板里的 `<!-- ... -->` HTML 注释写入产物；**仅**保留二级标题与 **「应用名 | 镜像 id」** 表格（**不要**表下 `>` 提示块，如「镜像 id 由人工填写…」）。
   - **「## 三、涉及的接口」**：以 **「接口列表」** 表为主；无特别说明时不写路径参数/成功响应/异常鉴权等子表（见模板）；**禁止**「本节为文本描述」等与事实不符的元说明；**禁止**以 `>` 引用块写入「对照 Controller / java-common / `.cursor/rules`」等**编写指引**。
   - **「## 四、SQL 脚本」**：无变更时**整节留空**（不要括号句「本期 PRD…」「无则本节留空」等）。
   - **「## 五、配置信息」**：无配置时**不要**填「无 | — | …」类**占位行**，**不要** `>` 提示「Apollo/脱敏」等；可**仅表头**或**空表**。
   - **「## 六、测试关注点」** 下**不要** `>` 综合说明块。
   - **「## 八、自测结果」** 下**不要**「由开发在提测前填写」等 `>` 提示。

2. **确定输出目录名 `执行目录名`（不用执行 ID）**：
   - 在已成功调用 **`get_executions_executionID`** 的前提下，取返回的 **`name`**（执行名称，如 `release_v2.6.2`）作为目录名来源。
   - **文件名安全化（slug）**：去除首尾空格；将 `\ / : * ? " < > |` 及不适合路径的字符替换为 `_`；合并连续 `_`；**不要**以 `.` 结尾；若结果为空，回退为 `exec-<executionID>`。
   - **目录冲突**：若 `onespec/checklist/<slug>/checklist.md` 已存在，读取其 Frontmatter `zentao-execution-id`：与本次 `executionID` **相同**则视为同一次执行更新，可覆盖；**不同**则在 `slug` 后追加 `_<executionID>` 作为最终目录名，避免误覆盖。
3. 读取模板：`.cursor/commands/spec-templates/checklist.md`。
4. 创建目录：`onespec/checklist/<执行目录名>/`。
5. 写入：`onespec/checklist/<执行目录名>/checklist.md`（第七节「相关文档」中的自引用路径须与之一致）。
6. 向用户汇报输出路径；提示 **多镜像** 时逐行核对；「待填写」行须提测前补全。

## 关键约束

- **禁止**在未成功取得禅道 MCP **有效调用结果**时编造工作项列表、标题或状态。
- **提测项目**可与禅道项目名称或执行名称对齐；**提测应用**（Frontmatter）为业务应用名；**第二节「应用名」列**为 **Git 仓库名**（如 `bfs-bemp`）；**镜像 id 可多个**，第二节表格多行，均须手动或确认占位。
- 路径以仓库根目录为基准；**`onespec/checklist/` 下子目录名 = 执行 `name` 的 slug，不用执行 ID**。
