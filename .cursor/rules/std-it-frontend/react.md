# React 最佳实践

## 组件结构
- 优先使用函数式组件而非类组件
- 保持组件小巧且专注
- 将可重用逻辑提取到自定义 Hook 中
- 使用组合优于继承
- 使用 TypeScript 实现适当的 Prop 类型
- 将大型组件拆分为更小、专注的组件

## Hooks
- 遵循 Hooks 规则
- 使用自定义 Hook 处理可重用逻辑
- 保持 Hook 专注且简单
- 在 useEffect 中使用适当的依赖数组
- 必要时在 useEffect 中实现清理操作
- 避免嵌套 Hook

## 状态管理
- 使用 useState 管理组件本地状态
- 使用 useReducer 处理复杂状态逻辑
- 使用 Context API 管理共享状态
- 将状态尽可能保持在靠近使用的位置
- 通过适当的状态管理避免 Prop 逐层传递 (Prop Drilling)
- 仅在必要时使用状态管理库

## 性能
- 实现适当的记忆化 (useMemo, useCallback)
- 对开销大的组件使用 React.memo
- 避免不必要的重新渲染
- 实现适当的懒加载
- 在列表中使用适当的 key 属性
- 分析并优化渲染性能

## 表单
- 使用受控组件处理表单输入
- 实现适当的表单验证
- 正确处理表单提交状态
- 显示适当的加载和错误状态
- 对复杂表单使用表单库
- 实现适当的表单无障碍性

## 错误处理
- 实现错误边界 (Error Boundaries)
- 正确处理异步错误
- 显示用户友好的错误消息
- 实现适当的回退 UI
- 适当记录错误
- 优雅地处理边缘情况

## 测试
- 编写组件单元测试
- 对复杂流程实现集成测试
- 使用 React Testing Library
- 测试用户交互
- 测试错误场景
- 实现适当的模拟数据

## 无障碍性 (Accessibility)
- 使用语义化 HTML 元素
- 实现适当的 ARIA 属性
- 确保键盘导航
- 使用屏幕阅读器测试
- 处理焦点管理
- 为图像提供适当的替代文本 (alt text)

## 代码组织
- 将相关组件分组在一起
- 使用适当的文件命名约定
- 实现适当的目录结构
- 将样式保持在靠近组件的位置
- 使用适当的导入/导出
- 记录复杂的组件逻辑
