# TDD 执行规则 - PHP 服务端

## 适用场景判断

| 条件 | 结论 |
|------|------|
| 用户标记 `[tdd]`/`[TDD]` | ✅ 强制 TDD |
| 用户标记 `[skip-test]` | ❌ 跳过 |
| 涉及**金额/权限/安全** | ✅ 强制 TDD |
| 复杂度 ≥3 分 | ✅ 必须 TDD |
| 公共/共享模块 | 🟡 建议 TDD |

**复杂度评分**（≥3分必须 TDD）：
- 代码 >50行(+1)、分支≫(+1)、状态机(+2)、Bug修复(+2)、重构(+2)、外部依赖(+1)

## AI 执行前必须

1. 读取 `composer.json`/`phpunit.xml` 识别测试框架
2. 读取现有测试代码了解项目风格
3. 评估复杂度，输出单测清单并等待确认

## Red-Green-Refactor 流程

**🔴 RED**：编写测试 → 运行确认失败（禁止写实现代码）

**🟢 GREEN**：编写最小实现 → 运行确认通过（禁止添加未测试功能）

**🔵 REFACTOR**：优化结构 → 运行确认仍通过（禁止改变行为）

## 测试规范

### 覆盖范围（四类必测）

| 类型 | 要点 |
|------|------|
| 正常路径 | 标准输入预期行为 |
| 边界条件 | 空字符串/空数组/null/最大最小值 |
| 异常处理 | 非法输入、依赖失败 |
| 数据一致性 | 事务回滚、幂等性 |

### FIRST 原则

- **F**ast：Mock 外部 IO，毫秒级完成
- **I**ndependent：测试间无依赖
- **R**epeatable：Mock 时间/随机数/外部依赖
- **S**elf-validating：用断言，不靠输出
- **T**imely：先写测试后写实现

### Mock 原则

| 场景 | Mock？ |
|------|-------|
| Repository/DAO | ✅ Mock |
| 外部 HTTP | ✅ Mock |
| 时间相关 | ✅ Mock |
| 私有方法 | ❌ 不 Mock |

## PHP 特有注意

- 测试代码也开启 `declare(strict_types=1);`
- 金额计算避免 float，或使用合适断言精度
- 避免依赖真实时钟/网络/随机数

## 禁止行为（红线）

- 复杂任务跳过测试
- 跳过时不告知用户
- 未读取项目文件直接生成测试
- 通过修改测试迁就错误实现
- 单元测试启动真实外部依赖（未声明）

## 输出格式

**豁免说明**（跳过时）：
```
💡 复杂度评估：【简单】(X分)
原因：[具体原因]
建议跳过单测。如需覆盖，请告知。
```

**单测清单**（执行前）：
```markdown
## 📋 单测清单 - [功能名称]

| # | 测试用例 | 状态 | 优先级 |
|---|---------|------|-------|
| 1 | [描述] | ⏳ | P0 |

**进度**：0/X (0%) ⏸️ 请确认后开始
```

**执行报告**（完成时）：
```markdown
## TDD 执行报告
| # | 测试用例 | 状态 |
|---|---------|------|
| 1 | [描述] | ✅ |
**结果**：X/X 通过
```

## 用户控制标记

| 标记 | 效果 |
|------|------|
| `[tdd]` | 强制 TDD |
| `[skip-test]` | 跳过单测 |
| `[need-test]` | 要求单测（非 TDD） |
| `[auto-confirm]` | 跳过确认环节 |
