# 任务拆解规则（轻量模式）

> 适用于 `--no-design` 场景：简单变更，影响模块 ≤2，总工时 ≤8h。
> 复杂变更请使用完整模式（去掉 `--no-design`）。

## 拆解原则

| 原则 | 规则 |
|------|------|
| **粒度控制** | 单任务工时 2h~4h；超过 8h **必须**拆分；低于 2h 合并至功能最相关的任务 |
| **可追溯性** | 需求追溯 ID 紧随任务标题第一行（`需求：{{REQUIREMENT_IDS}}`） |
| **信息完整性** | 每个任务须包含：预计工时 + 变更说明（文件路径 + 修改逻辑） |
| **依赖与并行** | 强依赖在描述中说明；可并行任务追加 `(P)` 标记 |

---

## tasks.md 必需章节（共 3 个）

1. **任务列表**：按需平铺，无需 `##` 模块分组
2. **任务统计**：总任务数、预计总工时（8h=1人天）
3. **风险提示**：关键依赖或不确定项（⚠️ 格式）；无风险则省略

---

## 禁止事项

- 禁止臆造 `proposal.md` 未提及的需求、工时
- 禁止单任务超过 8h 不拆分
- 轻量模式 tasks.md 开头须注明：`> ⚠️ 轻量模式：基于 proposal.md 拆解，未经详细设计，工时估算仅供参考。`
