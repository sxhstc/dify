# 需求分级体系

根据需求的复杂度、影响范围和风险等级，将需求分为 4 个等级。

## 分级总览

| 级别 | 名称 | 准出分数 | 工作量 | 适用场景 |
|------|------|----------|--------|----------|
| **S级** | 战略级 | ≥90分 | >20人天 | 新产品/多系统集成/核心流程重构 |
| **A级** | 核心级 | ≥85分 | 10-20人天 | 核心功能模块/跨模块协作 |
| **B级** | 常规级 | ≥70分 | 3-10人天 | 单一功能点/功能优化 |
| **C级** | 简单级 | ≥60分 | <3人天 | 文案修改/样式调整/配置变更 |

## 判断矩阵

| 维度 | S级 | A级 | B级 | C级 |
|------|-----|-----|-----|-----|
| **业务影响** | 核心业务流程 | 主要功能模块 | 单个功能点 | 辅助功能 |
| **用户范围** | 全部用户 | 大部分用户 | 部分用户 | 少量用户 |
| **技术复杂度** | 多系统集成/架构变更 | 跨模块/新技术 | 单模块实现 | 简单修改 |
| **风险等级** | 高风险 | 中高风险 | 中风险 | 低风险 |
| **依赖关系** | 被多个需求依赖 | 2-3个依赖 | 1个依赖 | 无依赖 |
| **数据影响** | 核心数据模型变更 | 新增数据表 | 修改数据字段 | 仅查询数据 |

**判断规则**：
- 满足 3 项及以上某级别特征 → 归入该等级
- 有争议时，按最高等级计（就高不就低）
- P0 优先级需求至少为 A 级标准

## 快速判断流程

```
收到需求
    ↓
是否影响核心业务或多系统集成？ ──是──→ S级
    ↓否
是否涉及新功能模块或跨模块协作？ ──是──→ A级
    ↓否
是否涉及业务逻辑或数据变更？ ──是──→ B级
    ↓否
是否仅为 UI/文案或配置调整？ ──是──→ C级
```

## 典型场景示例

### S级示例
- 用户认证系统升级（涉及安全）
- 支付系统对接
- 数据中台建设
- 核心业务流程重构
- 多系统深度集成

### A级示例
- 项目管理模块开发（CRUD 完整功能）
- 任务分配与跟踪功能
- 权限管理功能
- 报表统计功能
- 文档协作功能

### B级示例
- 列表页筛选条件新增
- 导出功能优化
- 表单字段调整
- 搜索功能改进
- 通知提醒功能

### C级示例
- 按钮文案修改
- 列表新增一列展示
- 页面布局微调
- 提示信息优化
- 权限开关配置

## 升级/降级规则

### 升级场景

**C级 → B级**：
- 发现涉及数据库字段变更
- 发现影响现有业务逻辑
- 发现需要兼容性考虑

**B级 → A级**：
- 发现涉及权限/安全问题
- 发现需要跨系统调用
- 发现影响其他模块（依赖方 >2 个）

**A级 → S级**：
- 发现影响核心交易流程
- 发现需要多系统深度集成
- 发现涉及数据迁移

### 降级场景

**A级 → B级**：
- 原计划跨模块，实际单模块可实现
- 技术复杂度低于预期

**B级 → C级**：
- 无数据库变更
- 无业务逻辑变更
- 纯前端展示调整
